# Autobile 0.9.3

This patch reduces repeated inference overhead in screenshot-driven automations.

## Performance

- Once a runtime successfully answers the first visual turn, later turns in the same
  task try it first instead of repeating known-unsuccessful lower tiers.
- A failed preferred runtime still falls back through the user's configured routing
  order.
- Game screenshots use a 1024-pixel longest edge and a smaller JPEG payload.
- Visual action responses use a 256-token budget for the bounded JSON decision.

## Safety

- Local-only execution never reuses a cloud runtime.
- Every turn still uses a fresh screenshot.
- App containment, Android system-edge exclusion, gesture checks, screenshot consent,
  and two fresh completion confirmations remain enforced.
