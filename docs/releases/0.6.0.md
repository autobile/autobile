# Autobile 0.6.0

This release closes a runtime failure that prevented on-device visual reasoning after
Autobile opened the app it was controlling. AICore's background restriction is now
treated as a device-runtime limitation, allowing an explicitly configured cloud tier to
continue the same request without weakening genuine policy refusals.

## Reliability

- Continue screenshot grounding when an app exposes no accessibility root.
- Preserve tap, long-press, swipe, and scroll semantics after visual grounding.
- Require fresh visual change or an observed text value before accepting a visually
  grounded action as successful.
- Validate declared outcomes against fresh pixels when the accessibility tree cannot
  describe the result.
- Preserve secure-window and screenshot-capture failures as explicit blocked states.
- Retain the last observed foreground package for rootless canvas and game surfaces.

## Runtime routing

- Distinguish AICore `BACKGROUND_USE_BLOCKED` from user or provider policy denial.
- Escalate a background-restricted Nano request only through tiers already permitted by
  the user's local/cloud policy.
- Keep genuine policy denials terminal.

## Verification

The release workflow runs Android lint, all unit tests, debug assembly, minified release
assembly, APK signature verification, and SHA-256 generation from the protected `main`
commit before publishing artifacts.
