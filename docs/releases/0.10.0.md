# Autobile 0.10.0

This release expands autonomous execution from learned routines to bounded one-off
visual tasks and improves recovery on canvas, game, and rich-editor interfaces.

## Direct tasks

- A natural-language request can run immediately in the current or named app without a
  saved demonstration when an image-capable runtime is available.
- Direct tasks remain package-contained, require confirmation, and use the same kill
  switch, history, risk, and completion-validation pipeline as saved automations.

## Visual execution

- Visual tasks can tap, long-press, swipe, wait, and enter text from a fresh screenshot.
- Compact working memory preserves puzzle state and other cross-turn facts without
  turning the screen interaction into a fixed coordinate macro.
- Each action records whether the next frame showed visible progress, helping the next
  turn avoid ineffective repetition.
- Agent banners and touch indicators are removed for the capture frame so they cannot be
  mistaken for controls in the target app.

## Reliability

- Demonstrated text focus points provide a package-scoped fallback for rich editors that
  expose no editable accessibility node.
- Screenshot validation can confirm text in editors whose accessibility tree does not
  report the resulting contents.
- Subscription model discovery retains alternate image-capable candidates and retries a
  different candidate when a model rejects image input or is unavailable.
- Natural-language step editing now supports text entry, swipes, and app launches in
  addition to the existing insert, replace, and delete operations.

## Safety

- Direct tasks do not become saved automations without an explicit teaching flow.
- System edges, app exits, ads, purchases, deletion, and external messaging remain
  blocked in the visual action loop.
- Completion still requires two independent fresh-screen confirmations.
