# Autobile 0.7.0

This release strengthens visual-only automation and makes the AI runtime policy an
explicit user choice.

## Visual-only reliability

- Continue through screenshot grounding when games, canvases, and embedded surfaces
  expose no accessibility nodes.
- Re-capture and re-ground after an unverified visual action instead of returning to a
  stale accessibility locator.
- Tell the vision runtime which points already failed so recovery does not repeat the
  same coordinate.
- Validate point actions against pixel feedback around the selected control, preventing
  unrelated game animation from being mistaken for success.
- Keep a task deferred when no vision runtime is currently available; do not misreport
  the target as absent.
- Distinguish rate limits, lost windows, missing screenshot access, internal capture
  errors, and secure windows so only the protected-content case is terminal.

## Runtime choice and onboarding

- Add on-device-first and cloud-first runtime preferences. Deterministic execution and
  the risk engine remain ahead of both choices.
- Explain the reduced capability of phones without on-device AI during onboarding.
- Offer ChatGPT Subscription browser sign-in as the primary vision setup on those
  devices, with explicit permission for screenshot use and sensitive-field masking.
- Recognize subscription sessions in live capability detection without requiring an
  OpenAI API key.
- Keep the same runtime priority control available later in Settings.

## Verification

The protected branch gate runs Android lint, debug unit tests, debug assembly, minified
release assembly, and an API 30 minified-APK startup smoke test. The release workflow
then rebuilds, signs, and verifies the APK from the tested merge commit.
