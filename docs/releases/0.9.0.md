# Autobile 0.9.0

This release makes dynamic visual automation a compilation mode rather than an edit-only
special case.

## Added

- Demonstrations are classified as fixed-step or visual-agent tasks. A game, puzzle,
  canvas, or changing board becomes one objective-driven loop that observes a new
  screenshot before every action.
- Plain-language corrections can insert, replace, or delete executable steps through a
  bounded action vocabulary. Both the post-demonstration correction field and the saved
  automation editor use the same path.
- Visual tasks may choose up to 256 taps, long presses, exact swipes, or waits while
  working toward independently declared visible completion criteria.

## Behavior

- The model may choose actions that were not demonstrated when the current screen shows
  they are necessary for progress.
- Deterministic app launch is preserved. A recorded exit is retained only when the edit
  plan explicitly requests it and remains unreachable until completion is confirmed.
- Completion still requires two fresh visual confirmations. Screen change alone is not
  success.

## Safety and limits

- Structural edits are previewed and use a closed action vocabulary; arbitrary code is
  never generated or executed.
- Visual actions remain inside the learned app, avoid Android system edges, and block
  purchases, ads, destructive actions, and unproven gestures.
- Secure windows, anti-cheat gesture blocking, and unavailable image runtimes are not
  bypassed. Model reasoning quality can still limit whether a particular puzzle is
  solved correctly.

## Upgrade

Install over an existing version. Existing automations and ChatGPT Subscription sessions
are retained. Re-save an older fixed-click game automation or apply a structural edit to
compile it as a visual-agent task.
